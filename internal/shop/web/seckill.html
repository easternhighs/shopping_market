点上面的按钮试试。抢购请求会先经过 Redis 判断「还有没有库存」，再排队进 Kafka。

这一单背后发生了什么

  1. 你点了按钮 → 请求打到 /seckill/items/<id>/orders。
  2. Redis 一锤定音：库存够不够、你是不是已经买过、是不是重复提交、是不是点太快—— 全在一段 Lua 脚本里一次算完，只花一次网络往返。
  3. 接口立刻回你「排队中」：这时候数据库里还没有这张订单，只有 Redis 扣了库存。
  4. Kafka 排队 → 消费端落库：后台的消费端把订单批量写进 MySQL，写完之后「我的秒杀订单」里才会出现它。
  5. 所以你看到的顺序是：排队中 → 已抢到（订单号出现）。中间那几百毫秒，就是这套异步架构的代价， 换来的是一万次点击不会把数据库打死。
